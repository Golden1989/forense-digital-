# WhatsApp Viewer (iOS and Android)

A local Python tool to **read and review the WhatsApp conversations of a forensic extraction** (SQLite database) in a web interface that runs on your own computer. It exists to speed up triage: pick a conversation, read messages with date and time, listen to voice messages, view images, list the members of a group, and export what matters for the report.

- **Read-only.** The database and the media folder are never modified. The database's SHA-256 is shown at the top of the page so you can record it in the report.
- **Fully local.** The server only answers on `127.0.0.1` (this computer). The viewer sends nothing to the internet.
- **Nothing to install** for the viewer (Python standard library only). Audio transcription and EXIF reading are optional and need extra libraries (see [Installation](#installation)).
- **No case data included.** This repository contains no database, media or transcript from any case. You point the tool at *your* evidence.

> **Transparency:** the code in this folder was developed with AI assistance (Claude, by Anthropic) and tested with anonymized sample databases (not included). Review it before relying on it in real work, and always check what the tool shows against the original database.

## Folder contents

| File | Purpose |
|---|---|
| `visualizador_whatsapp.py` | The viewer (local server + browser interface) |
| `transcrever_audios.py` | Generates automatic transcripts of voice messages (speech → text), optional |
| `requirements.txt` | Optional libraries (`faster-whisper`, `pillow`) |
| `README.md` / `README.en.md` | This guide, in Portuguese and English |

## What you need

Python 3.8 or newer (tested with 3.13). Check with `python --version` (on Windows, try `py --version` if `python` is not recognized and use `py` instead of `python` below).

And the extraction files (the tool does **not** ship them):

| System | Messages database | Contacts (optional, gives names to numbers) | Media (optional) |
|---|---|---|---|
| **iOS** | `ChatStorage.sqlite` | `Contacts.sqlite` | `Media/files/` folder (with `Audio/` and `Image/`) |
| **Android** | `msgstore.db` | `wa.db` | not supported in this version |

If the database comes with `-wal` and `-shm` files next to it, **keep them in the same folder**: the WAL holds recent changes not yet merged into the main database. When the `-wal` has data, the program works on a temporary copy of the three files (deleted on exit) so those changes show up and the original stays untouched.

## Installation

Open a terminal in the repository folder.

- **Viewer:** nothing to install.
- **EXIF reading for images (optional):** `pip install pillow`
- **Audio transcription (optional):** `pip install faster-whisper`

Or both: `pip install -r ferramentas/visualizador_whatsapp/requirements.txt`.

## Running

All commands run from the repository folder. Replace the paths with your evidence's.

**iOS**, everything in one folder (the program finds the database, contacts and media by itself):

```
python ferramentas/visualizador_whatsapp/visualizador_whatsapp.py --pasta "C:\evidence\ios"
```

**iOS**, pointing to each file:

```
python ferramentas/visualizador_whatsapp/visualizador_whatsapp.py --db "C:\evidence\ChatStorage.sqlite" --contatos "C:\evidence\Contacts.sqlite" --midia "C:\evidence\Media\files"
```

**Android:**

```
python ferramentas/visualizador_whatsapp/visualizador_whatsapp.py --db "C:\evidence\msgstore.db" --contatos "C:\evidence\wa.db"
```

The browser opens at `http://127.0.0.1:8765/`. Press `Ctrl+C` in the terminal to stop. (Option names are in Portuguese, as in the rest of this repository.)

| Option | What it does |
|---|---|
| `--pasta` | Folder with the database (`ChatStorage*.sqlite` or `msgstore*.db`) and contacts; media is looked up in `<folder>/Media/files` |
| `--db` | Messages database path (iOS or Android; the type is detected automatically) |
| `--contatos` | `Contacts*.sqlite` (iOS) or `wa*.db` (Android): contact names and, on Android, the block list |
| `--midia` | `Media/files` folder (with `Audio/` and `Image/`) if not in the default place |
| `--transcricoes` | JSON produced by `transcrever_audios.py` (shows the text under each voice message) |
| `--hash-banco` | Database SHA-256 recorded at acquisition. The program compares it with the computed hash and reports whether it **matches** |
| `--manifesto` | Reference CSV (generated by the **Integridade** panel) used to flag **altered**, new and missing media files |
| `--porta` | Local port (default `8765`). Change it if it is in use, or to open two databases at once |
| `--sem-navegador` | Do not open the browser automatically |

## Using the interface

- **Top bar:** database opened, number of conversations and messages, how many have a real date, how many voice messages/images have a file, and the **database SHA-256** (click to copy). On the right: **time zone** (default UTC-3) and light/dark **theme**.
- **Integrity (button in the top bar):** a table of **every media file in the folder**: real format, file size vs. size recorded in the database, modification time on disk, how many messages reference it, SHA-256 and alerts (extension mismatch, size mismatch, file no message references). *Exportar CSV* produces a **manifest** (hash list). To find out which files were **altered**: export the CSV right after acquisition and keep it with the evidence; later run the viewer with `--manifesto manifesto_aquisicao.csv` (and `--hash-banco <acquisition SHA-256>` if you have it). Each file is then marked **igual** (same), **ALTERADO** (different hash) or **novo** (new), and files that disappeared are listed as missing. Without a manifest the program **cannot claim** a file was altered; it only flags inconsistencies.
- **Conversation list:** filter by name or number; *All / Individual / Groups*; sort by most recent, oldest, most messages or name; show only conversations with playable audio or viewable images; *search text in ALL conversations* (Enter), including transcripts.
- **Conversation header:** type, identifier, message counts, sent/received, audio, images, period.
- **Group members:** in groups, the "Participantes do grupo" row opens a table with name, number, role (admin/member), status, messages sent in the group and first/last message, with CSV export.
- **Search in this conversation** (↑ ↓ between hits) and **message filter**: all, text only, sent, received, media, audio (all / with file / with transcript), images (all / with file), links, **only with CPF, phone number or e-mail** (together or separately), events, undated.
- **Go to** a given day, *Início* (start) and *Fim* (end) buttons, and **CSV export** of the conversation (direction, sender, date/time, raw date value, type, text, file, file SHA-256, real format, transcript, size, dimensions).
- **Messages:** day separators; hover the time to see the raw value stored in the database; message ID; ★ for starred; clickable links; group events as separate lines.
- **Voice messages:** built-in player, file name, SHA-256, real format and, with `--transcricoes`, the transcript (flagged as automatic).
- **Images:** thumbnail; click to enlarge (← → and `Esc`), with origin message, file name, real format (read from the first bytes, not the extension), dimensions, size, SHA-256 and EXIF (camera, dates, GPS) when present and Pillow is installed. Red alerts when the **extension does not match the real format** or the **file size differs from the size recorded in the database**.

### Audio transcription (optional)

Runs **on your computer** (the first run downloads the model; afterwards it works offline) and is slow: try `--limite 5` first. It can be interrupted and resumed.

```
python ferramentas/visualizador_whatsapp/transcrever_audios.py --pasta "C:\evidence\ios\Media\files\Audio" --saida transcricoes_audio.json
```

Options: `--modelo` (`tiny`, `base`, `small` default, `medium`, `large-v3`), `--idioma` (default `pt`, `auto` to detect), `--dispositivo` (`cpu` or `cuda`), `--limite N`. Then open the viewer with `--transcricoes transcricoes_audio.json`.

> Transcripts are **automatic and may be wrong** (names, slang, noise, accents). Use them for triage and **confirm by listening**. In a report, never quote them as the literal speech.

## Reading the output (forensic cautions)

- The viewer shows **what the database records**, not necessarily what happened. Absence of data does not prove it never existed.
- **Anonymized databases** (as used in coursework) may be deliberately altered: removed dates (those messages appear in database order, **with no day or time; do not invent dates for them**), shortened numbers with `~N` suffixes when two numbers collided, and invisible characters at the end of Android numbers (the program strips them to group conversations).
- **Dates.** iOS stores seconds since 2001-01-01 (Cocoa); Android stores milliseconds since 1970-01-01. The program converts them to the chosen time zone; the raw value shows on hover.
- **"Possible" CPF/phone:** the filter finds *text patterns* (CPF that is formatted or has valid check digits; numbers with area code; e-mails). It can produce false positives and negatives. Confirm by reading the message; in a report write "sequence *consistent with* a CPF".
- A group member shown as **"not active"** (iOS, `ZISACTIVE = 0`) is *consistent with* having left or been removed; the database does not say which, or when.
- Unconfirmed Android message types appear as `tipo_N_android_nao_confirmado`. Do not draw conclusions from them without checking.
- **"Modified on disk"** (Integrity panel) is the file date on the copy you opened; it usually reflects the copy/extraction, not when the media was created on the device.
- **File alteration** can only be asserted against a manifest or reference hash. Extension or size mismatches are *indicators* (they may result from anonymization, conversion or partial extraction), not proof of tampering.
- **Media:** only files present in the folder can be played/viewed. It is common for the database to list thousands of media items while the extraction contains a fraction.
- Quoted replies, forwards, calls, videos and deleted messages are not shown in this version.

## Privacy and GitHub

**Never push** the database, media, exported CSVs or the transcript JSON to GitHub: they are case data. The root `.gitignore` already blocks `*.db`, `*.sqlite*`, `*.csv` and `transcricoes*.json`. Run `git status` before every commit.
